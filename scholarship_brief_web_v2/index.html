A pipeline-level defense framework that wraps LLM agents inside a multi-stage quality-control loop to resist indirect prompt injection while preserving benign utility.

Research Background

Why Agent Safety Is Hard

LLM agents now read emails, book travel, and transfer money. A single injected instruction hidden in a web page or tool output can hijack the entire execution loop. Existing defenses fail because they treat safety as a one-time decision rather than a pipeline property.

🔒

We Need Structural Harnesses

Safety must be enforced across the full execution pipeline: input parsing, planning, gating, and action. A harness wraps the agent loop so that untrusted content can be inspected, quarantined, and sanitized before it ever reaches a sensitive tool.

Defenses must act after the model has already seen the injection but before it issues harmful tool calls.

🎯 The Core Problem: Indirect Prompt Injection

The attacker does not need to control the system prompt. They only need to poison content the agent will later read—an email, a webpage, a calendar invite, or a retrieved document.

⚠️ Prompt Hardening Collapses

System prompts and spotlighting rely on the model's own judgment. They fail when the payload adapts style or exploits instruction hierarchy.

🛡️ Peripheral Filters Are Too Narrow

Per-message classifiers and tool allow-lists miss attacks spread across multiple tool calls or reusing tools the benign task needs.

Approach

A Unified Approach: Pipeline + Gating

Instead of a standalone filter, the harness wraps the agent loop in a four-stage quality-control pipeline. Every stage is observable, reversible, and fail-closed.

Untrusted zone: raw inputs still carry adversarial risk
Gate: the single trust-decision boundary
Trusted zone: only sanitized actions execute
1

Structural Pre-processing

Parses heterogeneous content into semantic chunks and applies controlled transformations to expose inconsistencies.

Concrete Example
A "landlord notice" email arrives with an IBAN in the body. The harness separates the legitimate rent task from the injected payment instruction before planning.
2

Risk-Aware Gate

Tracks provenance across the execution trace and escalates scrutiny on suspicious patterns.

Concrete Example
After reading a webpage, the agent suddenly calls read_channel_messages on every Slack channel. The gate flags this as a cross-tool drift.
3

Scoped Sanitization

Strips transit-only metadata and routing cues after the gate so injected instructions cannot survive into trusted context.

Concrete Example
The injected HTML envelope found in a tool output is removed before the next planning step receives the cleaned result.
4

Trusted Execution

Issues tool calls only from the sanitized context and logs all side effects for audit.

Concrete Example
Because the send_money routing context came from an untrusted file, the harness blocks the transaction and returns a sanitized error.
E

Stress-Gated Evaluation

Only compares defenses on batches where the no-defense baseline is genuinely under attack pressure.

Concrete Example
A direct-injection batch is excluded because the unprotected agent already refuses the request, so it cannot measure defense improvement.
M

Model-Agnostic Driver

Declarative YAML configs and interchangeable backends let the same harness run on local, HF, and API models.

Concrete Example
The same 24-batch evaluation runs on DeepSeek and Llama 3.3 70B by changing one config line, with no code edits.

Why This Matters

As LLM agents move from demos to production, the attack surface shifts from the model to the agent execution loop. This project contributes a reusable framework for building structural, fail-closed harnesses around agents—so that future defenses can be evaluated and deployed without rewriting the safety layer from scratch.
